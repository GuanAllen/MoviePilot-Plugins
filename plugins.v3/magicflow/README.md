# MagicFlow - 魔流插件

根据站点魔力公式自动优化做种，智能删除低魔力产出种子。

## 功能特性

- **魔力公式计算**: 根据站点魔力公式精确计算每个种子的魔力产出效率
- **智能删种**: 按魔力产出从低到高排序，结合多种规则确定删除名单
- **魔力保护**: 支持魔力保护阈值和最低魔力值设置，防止魔力过低
- **多站点支持**: 通过站点适配器支持不同站点的魔力公式
- **刷流兼容**: 保留原有刷流插件的规则（做种时间、分享率、大小限制等）

### 跨站免费取种（3.9.0 / 3.10.0 改用 MP 搜索选源）

**玩法**：本站某颗「下载量大」的种子如果在**本站不免费**（下载就烧流量、拉低分享率），
改去**任意他站**找「**免费且同一 Release**」的副本下回来，下完再把这批文件**辅种回本站** ——
对本站来说是「零下载纯做种」，白赚上传与魔力。

任务配置「高级」→ **跨站免费取种**：

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| 启用跨站免费取种 | 关 | 打开后，本站不免费的候选会先尝试跨站取种 |
| 每轮跨站名额 | 3 | 每轮刷流最多发起几个跨站取种（防一次打太多站） |
| 单种大小上限 | 20 GB | 超过此体积不做跨站取种 |
| 最多探测站点数 | 6 | 每个候选最多查几个他站（越大越慢/越耗 PV） |

**判同 Release 的硬标准**：`fingerprint()` **完整特征码**（文件列表 + 根目录名）一致；
根目录名不同一律不自动辅种（在 qB 里会变成两个目录/对不上）。

**选源靠 MoviePilot 自带搜索**（3.10.0 起）：用 `SearchChain.search_by_title` 一次查多个站 ——
返回结果天然带 `downloadvolumefactor`（免不免费）、`seeders`（有没有源）、`freedate`（促销到期）、
`enclosure`（下载链）与站点 cookie，**免不免费不用再单独查**。
插件只保留「免费（`dv<=0`）且在做种（`seeders>=1`）」的行，再按「标题相似 + 体积邻近」预筛，
最后取他站 `.torrent` 用完整特征码定论（这一步本来就要下种，不多花 PV）。
（传 `rule_groups=[]`，**不套用 MP 的搜索过滤规则**，否则结果会被用户的规则筛掉。）

**免费任务也能跨站**（3.10.0）：任务选了「免费」时，本站非免费的候选以前在洗池阶段就被丢掉了，
根本进不了跨站逻辑；现在会把这类「**仅因非免费被洗掉、其他条件都合格**」的候选收进独立
**跨站候选池**（每轮最多探测 `CROSSSEED_EXTRA_SCAN=5` 个），只走跨站、**绝不从本站下**。

**PV 成本**：MP 搜索按站计（搜 N 个站 = N PV，结果缓存 6 小时）；跨站候选池每个候选要在本站
取一次 `.torrent`（1 PV）才拿得到特征码。想省 PV 就把「最多探测站点数」调小。

**IYUU（可选）**：填了 Token 时，先用 IYUU 反查「哪些站确实有这资源」，把 MP 搜索的站点范围缩到这几家，省 PV。

**回辅**由插件级单 worker「跨站回辅」（5 分钟一轮）完成：他站下完 → 把本站的 `.torrent`
指向同一批文件添加（暂停 → 校验 → 通过才做种，不匹配自动撤销）。超 24 小时未完成自动丢弃。

查看队列：`GET /crossseed`（`POST /crossseed?action=clear` 清空）。

#### ★ 来源份的 H&R 保种保护（3.11.1）

跨站取种是「**从兄弟站免费下**」——那份**来源种**在兄弟站仍然背着 H&R 保种义务
（例：**学校 BTSchool 要求挂种 10 小时**）。它**不归任何任务管**，所以以前会被来源站的
「同站纳管」逻辑抢走标签（实测 `SET tags=['魔流-财神']`），再被任务清理**连文件一起删掉**
—— 既踩来源站 H&R，又可能把目标站正在做种的**同一批文件**一起干掉。

3.11.1 起：

- **账本**：回辅成功**或失败**（数据都已经下下来了，义务照样在）都会把来源份写入
  `crossseed_sources`（PluginData 持久化），记下 `seed_until`（保种到什么时候）。
- **保护**：保种期内，来源份被并入所有清理的「保护集合」——
  `_cleanup_round` 的资产闸门、站点监控的「清非免费下载种」、同站「纳管/打标签」全部跳过它；
  一旦被谁改了标签，下一轮会**自动改回 `魔流-跨站`**（标签确权）。
- **时长**：站点级覆盖 > 全局默认。设置面板「跨站」页可配：
  「默认最短保种时长（小时）」（默认 24）、「站点保种时长（域名=小时）」
  （默认内置 `pt.btschool.club=10`，即学校 10h）。
- **回收**：默认**不回收**（免费种做种不花钱，还能攒来源站魔力/分享率）。
  真要回收，打开「H&R 期满后回收来源份」→ 只在**期满后**执行，且**只删种子、不删文件**
  （文件还归目标站那份用）。
- **兜底 vs H&R 的优先级**：流量兜底（判「免费」判错）**优先** —— 一旦真的在烧下载量，
  立即删种 + 拉黑来源站（H&R 让位于流量止损，该站也会被拉黑不再用）。
- **自愈**：升级前遗留的、带 `魔流-跨站` 标签但不在账本里的种，会自动回填进保护账本。

**诊断端点**（排查用，都要超管 JWT）：

| 端点 | 作用 |
| --- | --- |
| `GET /debug/mpsearch?keyword=&sites=8,9` | 直调 MP 搜索，看签名兼容/免费且有源命中（**1 PV/站**） |
| `GET /debug/crossseed?task=<id>&n=3[&add=true][&dump=1]` | 把该站候选**当成本站非免费**跑一遍跨站选源链路（dry-run；`add=true` 才真下；`dump=1` 打印两边文件清单，用于判断「特征码不同」是真不同还是仅根目录名不同） |
| `GET /debug/cache[?dump=<key>/drop=<key>/prefix=<str>]` | 看/丢站点抓取缓存（丢过之后下一轮强制重抓） |

### ★ 站点规则库（H&R / 最短保种 / 做种上限，3.12.0）

跨站取种的「来源份」在**兄弟站**仍背 H&R 义务（例：学校 BTSchool 要求挂种 10 小时），
而每条义务**只跟站点有关**。3.12.0 起这些规则**入库**，不再硬编码：

| 层 | 存放 | 说明 |
| --- | --- | --- |
| 内置 | `sites/rules.py: BUILTIN_RULES` | 人工核对的已知项（学校 10h、馒头无 H&R 且上限 100、红豆饭保守 24h） |
| 探测 | `site_rules`（`save_data`） | 抓站点页面（`/myhr.php`、`/rules.php`）解析出来，带证据片段 |
| 手填 | 设置「跨站 → 站点保种时长（域名=小时）」 | 最高优先级，一票覆盖 |

**生效优先级**：手填 > 探测 > 内置 > 全局默认（`crossseed_seed_hours_default`，默认 24h）。

**端点**：

| 端点 | 作用 |
| --- | --- |
| `GET /rules` | 规则列表（含每站**生效**保种时长与来源） |
| `GET /rules?action=probe[&site=<id\|域名>]` | **逐站拉取**：抓 H&R/规则页并入库（站点间随机歇 1.5~3.5s；受该站 PV 预算约束，不够就跳过） |
| `GET /rules?action=refresh` | 按 MP 已配置站点 + 内置表补全（**不触网**） |
| `GET /rules?action=set&site=<域名>&hours=<n>` | 手填覆盖（写进插件配置的「站点保种时长」） |

**保守原则**：解析是「宁保守勿乐观」—— 抓不到就保持原值，**绝不**把「没解析到」当成
「没有 H&R」。多挂几小时只是多点占用（免费种不花流量），少挂是实打实的惩罚。
解析顺带会抠出页面里的「做种数上限」。

**自动刷新**：worker「站点规则刷新」默认**每周**跑一次 `probe`（设置「站点规则」页可关）。

**界面**：设置面板新增「站点规则」页 —— 表格显示 站点 / 有无 H&R / 保种(h) / 做种上限 / 来源，
支持**逐站探测**、**一键全部拉取**、以及直接改保种时长（= 手填覆盖）。

### ⚠️ API 站的种子是「换票」地址，不能直接 GET（3.10.0 修）

馒头 / HDH / 肉丝 / 红叶 这类 **API 站**的 `enclosure` 不是直链，而是
`[base64(json)]url`：**先请求 url 换一张临时下载票，再从返回里取真实地址**。
MoviePilot 本体在下载链里会解这种格式，但插件自己取种字节时如果不解，
就只会去 GET 那个 API 地址 → 表现为「无法打开链接 / 本站取种失败」，
跨站选源（需要本站种子特征码）直接失效。
现 `downloader_ops.fetch_torrent_bytes` 已支持该格式（`method/params/header/proxy/result`
全按 MP 语义解析，返回磁力则跳过），命中的字节同时按「原始换票地址」缓存一份。

### ⚠️ 站点「免不免费」：别信 SDK 列表解析（3.10.0 修）

实测多套 NexusPHP 皮肤下，MoviePilot 自带 `TorrentsChain.browse` 经常**拿不到促销列**，
`downloadvolumefactor` 恒为 `0.0` —— 于是**所有种子都被当成「免费」**，魔力/双免/跨站判定全部失真。

因此主列表抓取改为：**NexusPHP 站优先走插件自己的直连解析**
（`browse_site_np_free(..., main=True)` → `_parse_np_rows` 读页面真实 `pro_free` / `promotion free`），
SDK `browse` 只作兜底（非 NexusPHP / 无 cookie 时）。抓取缓存 key 同步换成 `|<站>|main2|` 以作废旧缓存。

## 魔力公式

### HDFans

```
A = Σ((1 - 10^(-Ti/T0)) × Si × (1 + √2 × 10^(-(Ni-1)/(N0-1))) × Wi)
B = B0 × 2/π × arctan(A/L)

参数:
- Ti: 种子生存时间（周）
- T0: 生存时间参数，固定 5
- Si: 种子大小（GB）
- Ni: 当前做种人数
- N0: 做种人数参数，固定 7
- Wi: 权重（普通=1，零魔=0.2）
- B0: 小时魔力上限，固定 100
- L: 曲线参数，固定 300
```

## 开发

### 铁律：不要在函数体内写相对的懒导入（热重载死锁）

MoviePilot 热重载会先 `clear_modules()` 把 `app.plugins.magicflow*` 从 `sys.modules` 里全部清掉，
再单线程重新导入。如果此时你还有在飞的 worker 线程在函数体内执行 `from .x import y`，
两个线程就会形成**环形导入等待**：

```
重载线程 A：持有 app.plugins.magicflow（父包）→ 等 .sites
worker 线程 B：持有 app.plugins.magicflow.sites → 等父包（sites 里 from ..bonus import ...）
```

CPython 的 `_ModuleLock.has_deadlock()` 会检测到这个环并抛 `_DeadlockError`
（`deadlock detected by _ModuleLock('app.plugins.magicflow.sites')`）——**进程不会挂死**，
但那一次重载会失败：`sync.py` 报「同步本地插件失败」，MP 会把插件的全部服务摘掉
（`移除插件服务(None)`）直到下一次成功加载，期间定时任务不跑、插件 API 路由 404。

**做法**：所有相对的模块导入一律放**模块顶层**（必要时放在文件末尾、相关名字定义之后再导入）；
`import traceback` / `import base64` 这类**标准库**的懒导入无所谓（不涉及插件模块锁）。

## 版本号规则（语义化 · 强制）

格式 `MAJOR.MINOR.PATCH`，例：`1.1.0`。

| 改动类型 | 递增 | 例 |
| --- | --- | --- |
| 新功能 / 新标签页 / 新端点 | **+MINOR** | `1.1.0 → 1.2.0` |
| Bug 修复 / 文案 / 样式小改 | **+PATCH** | `1.1.0 → 1.1.1` |
| 不兼容变更（配置迁移、数据格式变） | **+MAJOR** | `1.1.0 → 2.0.0` |

- **PATCH 不超过 99**：到 99 后下一次改动改为 +MINOR 并把 PATCH 归零，**彻底避免 1.0.999 这类超长号**。
- **一次发版只 bump 一次**：一轮改动（一个功能或一批修复）只在收尾统一改版本号；开发中途验证靠硬刷新（`Ctrl+Shift+R`）或临时手动改 `?v`，**不要每改一点就 bump**（1.0.93~1.0.108 就是单改一个设置弹窗蹭出来的）。
- **必须同步的位置（缺一即市场/缓存错乱）**：
  1. `magicflow/__init__.py` → `__version__`
  2. `magicflow/package.json` → `version`
  3. 市场仓 `moviepilot-plugins-git/package.v3.json` → `version` + `history` 新条目
  4. 市场仓 `plugins.v3/magicflow/{__init__.py, package.json}` → `__version__` / `version`
  5. 本地市场索引 `core/local-plugins/package.v3.json` → `version` + `history`
  6. 本地仓 `core/local-plugins/plugins.v3/magicflow/{__init__.py, package.json}`
  7. 已安装副本 `config/plugins_backup/magicflow/`（由 monitor 自动同步覆盖，通常不用手改）
- **为什么必须 bump**：MoviePilot 插件前端走 `remoteEntry.js?v=<__version__>`，不 bump 客户端继续吃旧 chunk；`__version__` 同时是市场判定「有无更新」的依据。
